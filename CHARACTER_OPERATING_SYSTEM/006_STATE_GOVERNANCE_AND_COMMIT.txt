=== SECTION: STATE_GOVERNANCE_AND_COMMIT ===

[KEEP: Purpose & Role]
Single-writer commit authority for ChaOS. Runs twice per ordinary cycle: first as STATE_GOVERNANCE_AND_COMMIT_PRIMARY_PASS to commit ordinary lawful proposals, then as STATE_GOVERNANCE_AND_COMMIT_POST_VERIFICATION_PASS to commit verifier-originated governance-runtime proposals before scratchpad wipe. Reads proposals from [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY], validates against canonical, scheme, structural, and epistemic contracts, normalizes commit-bound artifacts, reconciles conflicts deterministically, commits lawful updates to STATE_* and STATE_GOVERNANCE_RUNTIME, and records full audit closure.

READ_VISIBILITY_CLASS: GOVERNANCE_INTERNAL

[KEEP: Relationship to Other Modules]
Informs:
- all persistent STATE_* modules
- STATE_GOVERNANCE_RUNTIME
- COT_UPDATE_VERIFICATION
- downstream audit inspection

Is Informed By:
- STATE_GOVERNANCE_OVERLAY
- CANONICAL_TOKEN_DICTIONARY
- UPDATE_CASCADE_REGISTRY
- all SCHEME_* modules
- all DYNAMICS_* modules
- [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY]
- STATE_GOVERNANCE_RUNTIME

=== SECTION: WRITE_POLICY_OVERRIDE ===

[[LLM_INSTRUCTION]]: This is the only normal persistent-state writer.

ALLOWED_WRITES:
- persistent STATE_* modules
- STATE_GOVERNANCE_RUNTIME
- [COGNITIVE_SCRATCHPAD][STATE_COMMIT_AUDIT]
- [COGNITIVE_SCRATCHPAD][OUTPUT_SURFACE_NORMALIZATION_AUDIT]
- [COGNITIVE_SCRATCHPAD][CASCADE_TRACE]

FORBIDDEN_WRITES:
- generation of unconstrained new proposals
- bypass of proposal registry
- mutation outside canonical paths
- prose narrative output during commit execution

[[LLM_INSTRUCTION]]: Commit execution is reduction-only. Commit steps produce structured audit fields exclusively. No narrative output is permitted between proposal intake and audit emission.

=== SECTION: TWO_PHASE_GOVERNANCE_EXECUTION ===

[[LLM_INSTRUCTION]]: STATE_GOVERNANCE_AND_COMMIT runs in two restricted modes per ordinary cycle. Both modes are invocations of the same single-writer authority.

PRIMARY_PASS:
- Execution slot: PRIORITY_16.
- Trace COT_NAME: STATE_GOVERNANCE_AND_COMMIT_PRIMARY_PASS.
- Consumes proposals present before COT_UPDATE_VERIFICATION.
- Commits lawful proposals targeting ordinary persistent STATE_* modules, STATE_TEMPORARY_MODIFIERS, and any governance-corrective proposals lawfully present at primary intake.
- Emits PRIMARY_PASS_AUDIT into [COGNITIVE_SCRATCHPAD][STATE_COMMIT_AUDIT].
- Appends exactly one governance trace entry.

POST_VERIFICATION_PASS:
- Execution slot: PRIORITY_18.
- Trace COT_NAME: STATE_GOVERNANCE_AND_COMMIT_POST_VERIFICATION_PASS.
- Runs after COT_UPDATE_VERIFICATION.
- Consumes only proposals generated by COT_UPDATE_VERIFICATION during PRIORITY_17.
- Lawful post-verification proposals must satisfy all of:
  - SOURCE_COT: COT_UPDATE_VERIFICATION
  - TARGET_MODULE: STATE_GOVERNANCE_RUNTIME
  - INVOKED_RULE_NAME: GOVERNANCE_CORRECTIVE
  - OPERATION_TYPE: SET
  - EPISTEMIC_TAG: PERCEPTION or INFERENCE
  - JUSTIFICATION_CATEGORY: DIRECT_APPLICATION
- Lawful target fields:
  - [STATE_GOVERNANCE_RUNTIME][LAST_VERIFICATION_RESULT]
  - [STATE_GOVERNANCE_RUNTIME][LAST_COMMIT_CYCLE_ID]
  - [STATE_GOVERNANCE_RUNTIME][QUARANTINE_MODE]
  - [STATE_GOVERNANCE_RUNTIME][QUARANTINE_ENGAGED_CYCLE_ID]
  - [STATE_GOVERNANCE_RUNTIME][QUARANTINE_REASON_CODES]
- All non-governance-runtime proposals encountered during POST_VERIFICATION_PASS are suppressed with POST_VERIFICATION_TARGET_FORBIDDEN.
- All governance-runtime proposals not emitted by COT_UPDATE_VERIFICATION during PRIORITY_17 are suppressed with POST_VERIFICATION_SOURCE_INVALID.
- Emits POST_VERIFICATION_PASS_AUDIT into [COGNITIVE_SCRATCHPAD][STATE_COMMIT_AUDIT].
- Appends exactly one post-verification governance trace entry.
- Scratchpad wipe occurs only after this pass completes.

SINGLE_WRITER_PRESERVATION:
- COT_UPDATE_VERIFICATION never writes directly to STATE_GOVERNANCE_RUNTIME.
- STATE_GOVERNANCE_AND_COMMIT remains the only persistent writer.
- The second pass is a restricted invocation of the same writer, not a second writer.

=== SECTION: PRIMARY_COMMIT_SEQUENCE ===

[[LLM_INSTRUCTION]]: Process primary-pass proposals in this deterministic order.

STEP_00_QUARANTINE_GATE:
- Read STATE_GOVERNANCE_RUNTIME.QUARANTINE_MODE.
- If QUARANTINE_MODE is TRUE:
  - Filter [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY] to retain only proposals with INVOKED_RULE_NAME = GOVERNANCE_CORRECTIVE.
  - Suppress all other proposals with reason code QUARANTINE_ACTIVE.
- If QUARANTINE_MODE is FALSE: proceed with all proposals available at primary intake.

STEP_01_PROPOSAL_INTAKE:
- Read retained entries from [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY].
- Exclude proposals generated later by COT_UPDATE_VERIFICATION because those do not yet exist during PRIMARY_PASS.
- Initialize audit totals and empty outcome logs.
- If registry is empty after STEP_00 filtering: emit zero-change primary audit and continue to STEP_11.

STEP_02_SCHEMA_COMPLETENESS_CHECK:
- Verify each proposal contains all REQUIRED_FIELDS per UPDATE_CASCADE_REGISTRY.PROPOSAL_ENTRY_SCHEMA.
- Verify CONDITIONALLY_REQUIRED_FIELDS per their conditions.
- Suppress malformed proposals with MALFORMED_PROPOSAL_SCHEMA.

STEP_03_CANONICAL_PATH_VALIDATION:
- Validate module root is in CANONICAL_MODULE_ROOTS.
- Validate bracket-path structure, target legality, and registry usage.
- Suppress with INVALID_PATH_ROOT or INVALID_TARGET_FIELD.

STEP_04_SCHEME_VALIDATION:
- Validate enum legality, ordinal legality, record schema compatibility, and invariant compatibility.
- Validate QUALITATIVE_INTENSITY band membership for STRENGTH and band-typed PROPOSED_VALUE fields.
- Suppress with INVALID_ENUM_VALUE, INVALID_ORDINAL_TRANSITION, REGISTRY_RECORD_PAIR_VIOLATION, SCHEME_INVARIANT_VIOLATION, MODIFIER_SCHEMA_VIOLATION, LINKAGE_REFERENCE_VIOLATION, or IMMUNE_TERMINAL_STATE_CONFLICT.

STEP_05_TRANSLATION_BEFORE_COMMIT:
- Normalize narrative fields to canonical English:
  - JUSTIFICATION
  - NOTES
  - RATIONALE
  - EFFECT_EXPRESSION
  - NARRATIVE_CUE_REFERENCE
  - SCHEME_INVARIANT_NOTE
- Preserve all write-surface tokens exactly.
- Suppress with TRANSLATION_VIOLATION if normalization would mutate a write-surface token.
- Write normalization status to [COGNITIVE_SCRATCHPAD][OUTPUT_SURFACE_NORMALIZATION_AUDIT].

STEP_06_EPISTEMIC_TAG_VALIDATION:
- Validate EPISTEMIC_TAG against closed enum.
- Validate JUSTIFICATION_CATEGORY against closed enum.
- Validate JUSTIFICATION_CATEGORY-to-EPISTEMIC_TAG mapping per CANONICAL_TOKEN_DICTIONARY.
- Suppress mismatch with JUSTIFICATION_CATEGORY_TAG_MISMATCH.
- Suppress invalid tag with EPISTEMIC_TAG_VIOLATION.
- For EPISTEMIC_TAG = TOOL_REQUEST: suppress with TOOL_ACTUATION_NOT_ACTIVE.

STEP_07_EVIDENCE_REF_VALIDATION:
- For EPISTEMIC_TAG = COMMITTED_FACT:
  - Verify EVIDENCE_REF present. If missing: COMMITTED_FACT_WITHOUT_EVIDENCE.
  - Verify EVIDENCE_REF resolves against persistent state per EVIDENCE_REF_VALUE_FORMS. If unresolvable: EVIDENCE_REF_UNRESOLVED.

STEP_08_OVERRIDE_PROOF_VALIDATION:
- Identify proposals triggering an override gate.
- For each, verify all four STRUCTURAL_OVERRIDE_PROOF_FIELDS present and lawful:
  - INVOKED_RULE_NAME
  - NARRATIVE_CUE_REFERENCE
  - SCHEME_INVARIANT_NOTE
  - MECHANISM_TAG
- Suppress missing or malformed proof with OVERRIDE_PROOF_INCOMPLETE.

STEP_09_CONFLICT_RECONCILIATION:
- Group proposals by effective target.
- Apply PRECEDENCE_ORDER and TIE_BREAKERS per STATE_GOVERNANCE_OVERLAY.CONFLICT_RESOLUTION_POLICY.
- Produce final candidate actions.

STEP_10_STEP_LIMIT_AND_DOWNGRADE_EVALUATION:
- Enforce per-cycle caps and step limits per STATE_GOVERNANCE_OVERLAY.STEP_LIMITS_PER_CYCLE.
- Enforce MAX_ACTIVE_PREDICTIONS for DPF prediction creations. Excess: DPF_PREDICTION_CAP_EXCEEDED.
- Apply override-proof gates from STEP_08 results.
- Downgrade excessive magnitude or step-size requests only when the nearest lawful bounded change is deterministic.
- Otherwise suppress with STEP_LIMIT_EXCEEDED, OVERRIDE_PROOF_MISSING, or BASELINE_REWRITE_NOT_JUSTIFIED.

STEP_11_PERSISTENT_COMMIT_AND_AUDIT:
- Apply final lawful committed writes to STATE_* modules, STATE_TEMPORARY_MODIFIERS, and STATE_GOVERNANCE_RUNTIME where lawful governance-corrective updates are present at primary intake.
- Write PRIMARY_PASS_AUDIT into [COGNITIVE_SCRATCHPAD][STATE_COMMIT_AUDIT].
- Append one governance trace entry to [COGNITIVE_SCRATCHPAD][CASCADE_TRACE] with COT_NAME STATE_GOVERNANCE_AND_COMMIT_PRIMARY_PASS.

=== SECTION: POST_VERIFICATION_COMMIT_SEQUENCE ===

[[LLM_INSTRUCTION]]: Process post-verification proposals in this deterministic restricted order.

PV_STEP_00_POST_VERIFICATION_INTAKE:
- Read proposals appended by COT_UPDATE_VERIFICATION during PRIORITY_17.
- Ignore proposals already closed by PRIMARY_PASS.
- Initialize POST_VERIFICATION_PASS_AUDIT.
- If no verifier-originated governance-runtime proposals exist: emit zero-change post-verification audit and continue to PV_STEP_07.

PV_STEP_01_SOURCE_AND_TARGET_GATE:
- Retain only proposals satisfying:
  - SOURCE_COT = COT_UPDATE_VERIFICATION
  - TARGET_MODULE = STATE_GOVERNANCE_RUNTIME
  - OPERATION_TYPE = SET
  - INVOKED_RULE_NAME = GOVERNANCE_CORRECTIVE
- Suppress proposals failing source check with POST_VERIFICATION_SOURCE_INVALID.
- Suppress proposals failing target check with POST_VERIFICATION_TARGET_FORBIDDEN.

PV_STEP_02_SCHEMA_COMPLETENESS_CHECK:
- Verify proposal schema completeness per UPDATE_CASCADE_REGISTRY.PROPOSAL_ENTRY_SCHEMA.
- GOVERNANCE_CORRECTIVE proposals must include NARRATIVE_CUE_REFERENCE and SCHEME_INVARIANT_NOTE.
- Suppress malformed proposals with MALFORMED_PROPOSAL_SCHEMA.

PV_STEP_03_CANONICAL_PATH_AND_FIELD_VALIDATION:
- Validate TARGET_FIELD is one of the lawful STATE_GOVERNANCE_RUNTIME fields for post-verification pass.
- Suppress unlawful target with INVALID_TARGET_FIELD.

PV_STEP_04_GOVERNANCE_RUNTIME_VALUE_VALIDATION:
- Validate PROPOSED_VALUE against SCHEME_GOVERNANCE_RUNTIME when available.
- Validate LAST_VERIFICATION_RESULT values are PASS, WARN, FAIL, or PENDING.
- Validate QUARANTINE_MODE values are TRUE or FALSE.
- Validate QUARANTINE_ENGAGED_CYCLE_ID is current commit cycle id or NONE.
- Validate QUARANTINE_REASON_CODES cap behavior at max 5 with FIFO eviction.
- Suppress invalid values with INVALID_ENUM_VALUE or SCHEME_INVARIANT_VIOLATION.

PV_STEP_05_TRANSLATION_AND_EPISTEMIC_VALIDATION:
- Normalize narrative fields to canonical English.
- Preserve write-surface tokens exactly.
- Validate EPISTEMIC_TAG and JUSTIFICATION_CATEGORY mapping.
- Suppress invalid proposals with TRANSLATION_VIOLATION, EPISTEMIC_TAG_VIOLATION, or JUSTIFICATION_CATEGORY_TAG_MISMATCH.
- COMMITTED_FACT is permitted only with lawful EVIDENCE_REF. Verifier governance-runtime proposals SHOULD use PERCEPTION or INFERENCE to avoid audit-reference evidence mismatch.

PV_STEP_06_RECONCILIATION_AND_COMMIT:
- Group retained proposals by target field.
- Apply conflict policy.
- Commit lawful STATE_GOVERNANCE_RUNTIME updates.
- Apply QUARANTINE_REASON_CODES cap-aware SET behavior.
- Write final action closure for each post-verification proposal.

PV_STEP_07_POST_VERIFICATION_AUDIT_AND_TRACE:
- Write POST_VERIFICATION_PASS_AUDIT into [COGNITIVE_SCRATCHPAD][STATE_COMMIT_AUDIT].
- Append one trace entry to [COGNITIVE_SCRATCHPAD][CASCADE_TRACE] with COT_NAME STATE_GOVERNANCE_AND_COMMIT_POST_VERIFICATION_PASS.
- Do not invoke COT_UPDATE_VERIFICATION again in the same cycle.

=== SECTION: COMMIT_BEHAVIOR_BY_OPERATION_TYPE ===

SET:
- Apply explicit value or payload to canonical target field when lawful.
- Registry SET pair behavior must preserve registry-record coherence.
- STATE_GOVERNANCE_RUNTIME SET operations in POST_VERIFICATION_PASS are limited to lawful governance-runtime fields.

TRANSITION:
- Resolve directional transition against current committed value and scheme ordering.
- Valid relative directives:
  - ONE_STEP_UP
  - ONE_STEP_DOWN
  - ONE_STEP_TOWARD_BASELINE
  - ONE_STEP_TOWARD_NEUTRAL
- Commit only the lawful resulting value.
- TRANSITION is not lawful during POST_VERIFICATION_PASS.

ADD_MODIFIER:
- Resolve modifier proposals deterministically per DYNAMICS_TEMPORARY_MODIFIERS.
- Evaluation order:
  1) Validate schema and target legality.
  2) Search for lawful active collision candidate per REFRESH_MATCH_FACTORS.
  3) If no collision candidate exists and coexistence is lawful, create new modifier by registry-record SET behavior.
  4) If materially same active modifier exists and STACKING_RULE = REPLACE, replace existing modifier in place using the same MOD_XX.
  5) If materially same active modifier exists and STACKING_RULE is not REPLACE, refresh existing modifier in place using the same MOD_XX.
  6) If materially different modifier exists on the same target, create new modifier only if coexistence is lawful and bounded; otherwise suppress.
- ADD_MODIFIER is not lawful during POST_VERIFICATION_PASS.

REMOVE_MODIFIER:
- Remove the targeted modifier from [STATE_TEMPORARY_MODIFIERS].
- Remove the corresponding MOD_XX from MODIFIER_REGISTRY.
- Preserve lifecycle closure in audit output rather than persistent retention.
- REMOVE_MODIFIER is not lawful during POST_VERIFICATION_PASS.

CAP:
- Apply bounded ceiling behavior where scheme and governance permit.
- Modifier cap behavior remains consistent with DYNAMICS_TEMPORARY_MODIFIERS.
- CAP is not lawful during POST_VERIFICATION_PASS unless later explicitly declared for governance runtime.

VETO:
- Suppress lower-precedence conflicting change or block disallowed mutation.
- VETO is not lawful during POST_VERIFICATION_PASS.
