=== SECTION: STATE_GOVERNANCE_AND_COMMIT ===

[KEEP: Purpose & Role]
Single-writer commit authority for ChaOS. Reads proposals from [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY], validates against canonical, scheme, structural, and epistemic contracts, normalizes commit-bound artifacts, reconciles conflicts deterministically, commits lawful updates to STATE_* and STATE_GOVERNANCE_RUNTIME, and records full audit closure.

READ_VISIBILITY_CLASS: GOVERNANCE_INTERNAL

[KEEP: Relationship to Other Modules]
Informs:
- all persistent STATE_* modules
- STATE_GOVERNANCE_RUNTIME
- COT_UPDATE_VERIFICATION
- downstream audit inspection

Is Informed By:
- STATE_GOVERNANCE_OVERLAY
- CANONICAL_TOKEN_DICTIONARY
- UPDATE_CASCADE_REGISTRY
- all SCHEME_* modules
- all DYNAMICS_* modules
- [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY]
- STATE_GOVERNANCE_RUNTIME (read for quarantine intake)

=== SECTION: WRITE_POLICY_OVERRIDE ===

[[LLM_INSTRUCTION]]: This is the only normal persistent-state writer.

ALLOWED_WRITES:
- persistent STATE_* modules
- STATE_GOVERNANCE_RUNTIME
- [COGNITIVE_SCRATCHPAD][STATE_COMMIT_AUDIT]
- [COGNITIVE_SCRATCHPAD][OUTPUT_SURFACE_NORMALIZATION_AUDIT]
- [COGNITIVE_SCRATCHPAD][CASCADE_TRACE]

FORBIDDEN_WRITES:
- generation of unconstrained new proposals
- bypass of proposal registry
- mutation outside canonical paths
- prose narrative output during commit execution

[[LLM_INSTRUCTION]]: Commit execution is reduction-only. STEP_00 through STEP_11 produce structured audit fields exclusively. No narrative output is permitted between proposal intake and audit emission.

=== SECTION: COMMIT_SEQUENCE ===

[[LLM_INSTRUCTION]]: Process proposals in this deterministic order.

STEP_00_QUARANTINE_GATE
- Read STATE_GOVERNANCE_RUNTIME.QUARANTINE_MODE.
- If QUARANTINE_MODE is TRUE:
  - Filter [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY] to retain only proposals with INVOKED_RULE_NAME = GOVERNANCE_CORRECTIVE.
  - Suppress all other proposals with reason code QUARANTINE_ACTIVE.
- If QUARANTINE_MODE is FALSE: proceed with all proposals.

STEP_01_PROPOSAL_INTAKE
- Read all retained entries from [COGNITIVE_SCRATCHPAD][PROPOSED_UPDATES_REGISTRY].
- Initialize audit totals and empty outcome logs.
- If registry is empty after STEP_00 filtering: emit zero-change audit and continue to STEP_10.

STEP_02_SCHEMA_COMPLETENESS_CHECK
- Verify each proposal contains all REQUIRED_FIELDS per UPDATE_CASCADE_REGISTRY.PROPOSAL_ENTRY_SCHEMA.
- Verify CONDITIONALLY_REQUIRED_FIELDS per their conditions.
- Suppress malformed proposals with MALFORMED_PROPOSAL_SCHEMA.

STEP_03_CANONICAL_PATH_VALIDATION
- Validate module root is in CANONICAL_MODULE_ROOTS.
- Validate bracket-path structure, target legality, and registry usage.
- Suppress with INVALID_PATH_ROOT or INVALID_TARGET_FIELD.

STEP_04_SCHEME_VALIDATION
- Validate enum legality, ordinal legality, record schema compatibility, and invariant compatibility.
- Validate QUALITATIVE_INTENSITY band membership for STRENGTH and band-typed PROPOSED_VALUE fields.
- Suppress with INVALID_ENUM_VALUE, INVALID_ORDINAL_TRANSITION, REGISTRY_RECORD_PAIR_VIOLATION, SCHEME_INVARIANT_VIOLATION, MODIFIER_SCHEMA_VIOLATION, or LINKAGE_REFERENCE_VIOLATION.

STEP_05_TRANSLATION_BEFORE_COMMIT
- Normalize narrative fields to canonical English: JUSTIFICATION, NOTES, RATIONALE, EFFECT_EXPRESSION, NARRATIVE_CUE_REFERENCE, SCHEME_INVARIANT_NOTE.
- Preserve all write-surface tokens exactly.
- Suppress with TRANSLATION_VIOLATION if normalization would mutate a write-surface token.
- Write normalization status to [COGNITIVE_SCRATCHPAD][OUTPUT_SURFACE_NORMALIZATION_AUDIT].

STEP_06_EPISTEMIC_TAG_VALIDATION
- Validate EPISTEMIC_TAG against closed enum.
- Validate JUSTIFICATION_CATEGORY against closed enum.
- Validate JUSTIFICATION_CATEGORY-to-EPISTEMIC_TAG mapping per CANONICAL_TOKEN_DICTIONARY.
- Suppress mismatch with JUSTIFICATION_CATEGORY_TAG_MISMATCH.
- Suppress invalid tag with EPISTEMIC_TAG_VIOLATION.
- For EPISTEMIC_TAG = TOOL_REQUEST: suppress with TOOL_ACTUATION_NOT_ACTIVE per RUNNABLE_BUT_LIFTABLE_RESERVATIONS.

STEP_07_EVIDENCE_REF_VALIDATION
- For EPISTEMIC_TAG = COMMITTED_FACT:
  - Verify EVIDENCE_REF present. If missing: COMMITTED_FACT_WITHOUT_EVIDENCE.
  - Verify EVIDENCE_REF resolves against persistent state per EVIDENCE_REF_VALUE_FORMS. If unresolvable: EVIDENCE_REF_UNRESOLVED.

STEP_08_OVERRIDE_PROOF_VALIDATION
- Identify proposals triggering an override gate (multi-step shift, cap-breach, baseline rewrite on immutable domain, MEMORY creation override, DPF prediction cap exception).
- For each: verify all four STRUCTURAL_OVERRIDE_PROOF_FIELDS present and lawful (INVOKED_RULE_NAME, NARRATIVE_CUE_REFERENCE, SCHEME_INVARIANT_NOTE, MECHANISM_TAG).
- Suppress missing or malformed proof with OVERRIDE_PROOF_INCOMPLETE.

STEP_09_CONFLICT_RECONCILIATION
- Group proposals by effective target.
- Apply PRECEDENCE_ORDER and TIE_BREAKERS per STATE_GOVERNANCE_OVERLAY.CONFLICT_RESOLUTION_POLICY.
- Produce final candidate actions.

STEP_10_STEP_LIMIT_AND_DOWNGRADE_EVALUATION
- Enforce per-cycle caps and step limits per STATE_GOVERNANCE_OVERLAY.STEP_LIMITS_PER_CYCLE.
- Enforce MAX_ACTIVE_PREDICTIONS for DPF prediction creations. Excess: DPF_PREDICTION_CAP_EXCEEDED.
- Apply override-proof gates from STEP_08 results.
- Downgrade excessive magnitude or step-size requests only when the nearest lawful bounded change is deterministic.
- Otherwise suppress with STEP_LIMIT_EXCEEDED, OVERRIDE_PROOF_MISSING, or BASELINE_REWRITE_NOT_JUSTIFIED.

STEP_11_PERSISTENT_COMMIT_AND_AUDIT
- Apply final lawful committed writes to STATE_* modules and STATE_GOVERNANCE_RUNTIME (where governance-corrective updates apply).
- Write final audit object into [COGNITIVE_SCRATCHPAD][STATE_COMMIT_AUDIT].
- Append one governance trace entry to [COGNITIVE_SCRATCHPAD][CASCADE_TRACE].

=== SECTION: COMMIT_BEHAVIOR_BY_OPERATION_TYPE ===

SET:
- Apply explicit value or payload to canonical target field when lawful.

TRANSITION:
- Resolve directional transition against current committed value and scheme ordering.
- Valid relative directives: ONE_STEP_UP, ONE_STEP_DOWN, ONE_STEP_TOWARD_BASELINE, ONE_STEP_TOWARD_NEUTRAL.
- Commit only the lawful resulting value.

ADD_MODIFIER:
- Resolve modifier proposals deterministically per DYNAMICS_TEMPORARY_MODIFIERS.
- Evaluation order:
  1) Validate schema and target legality.
  2) Search for lawful active collision candidate per REFRESH_MATCH_FACTORS.
  3) If no collision candidate exists and coexistence is lawful:
     - Create new modifier (append MOD_XX to MODIFIER_REGISTRY; write [STATE_TEMPORARY_MODIFIERS][MOD_XX] payload).
  4) If materially same active modifier exists and STACKING_RULE = REPLACE:
     - Replace existing modifier in place using the same MOD_XX.
  5) If materially same active modifier exists and STACKING_RULE is not REPLACE:
     - Refresh existing modifier in place using the same MOD_XX.
  6) If materially different modifier exists on the same target:
     - Create new modifier only if coexistence is lawful and bounded; otherwise suppress.
- In-place refresh or replacement does not create a new MOD_XX and does not grow the registry.

REMOVE_MODIFIER:
- Remove the targeted modifier from [STATE_TEMPORARY_MODIFIERS].
- Remove the corresponding MOD_XX from MODIFIER_REGISTRY.
- Preserve lifecycle closure in audit output rather than persistent retention.

CAP:
- Apply bounded ceiling behavior where scheme and governance permit.
- Modifier cap behavior remains consistent with DYNAMICS_TEMPORARY_MODIFIERS.

VETO:
- Suppress lower-precedence conflicting change or block disallowed mutation.
