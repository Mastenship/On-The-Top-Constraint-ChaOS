=== SECTION: COT_CHARACTER_INSTANTIATION_PROCESS ===

[KEEP: Purpose & Role]
Interactive guided workflow for first-time character seeding. Produces proposal-only initialization packets for mutable STATE_ values and instantiation-time immutable baseline SCHEME values. Governance commits approved seed proposals.

READ_VISIBILITY_CLASS: CHARACTER_VISIBLE

[KEEP: Relationship to Other Modules]
Informs: initial STATE_* seeds and permitted immutable baseline SCHEME seeds.
Is Informed By: user concept/background, SCHEME_ bounds, DYNAMICS_ bounds, CANONICAL_TOKEN_DICTIONARY, UPDATE_CASCADE_REGISTRY.

=== SECTION_BREAK ===

=== SECTION: WRITE_POLICY_OVERRIDE ===

[[LLM_INSTRUCTION]]: No direct persistent writes. All seeding intent is proposal-only.
[[LLM_INSTRUCTION]]: SET [COGNITIVE_SCRATCHPAD][TEMPORARY_STATE_FLAGS][INSTANTIATION_MODE] TRUE on workflow entry. Governance clears it on first non-instantiation cycle.

=== SECTION: INTERACTIVE_WALKTHROUGH_STRUCTURE ===

- HEXACO, DARK_TRIAD, MMPI, ASQ, moral/social/emotional profile.

LAYER_05_RELATIONAL_AND_MEMORY_SEEDS:
- key entities, formative relationships, defining events.

LAYER_06_COMMUNICATION_BELIEFS_AND_DPF:
- speech profile, worldview axes, predictive stance, interpretive style.

LAYER_07_GOALS_AND_DRIVES:
- initial motivations, drives, active goals.

LAYER_08_COLLABORATIVE_VERIFICATION:
- user coherence review and final seed approval.

=== SECTION_BREAK ===

=== SECTION: STRICT_SEEDING_CONTRACT ===

[[LLM_INSTRUCTION]]: CREATE_NEW_RECORD is forbidden. Registry-backed seeds use SET pair.
[[LLM_INSTRUCTION]]: Immutable baseline-bearing SCHEME seeds are lawful only during INSTANTIATION_MODE and only for modules listed in CANONICAL_TOKEN_DICTIONARY.IMMUTABLE_BASELINE_BEARING_MODULES.

REGISTRY_ENTRY_SET_PAIR:
- Proposal A:
  OPERATION_TYPE: SET
  TARGET_FIELD: [STATE_<DOMAIN>][<DOMAIN>_REGISTRY]
  PROPOSED_VALUE: append <ID_TOKEN>
- Proposal B:
  OPERATION_TYPE: SET
  TARGET_FIELD: [STATE_<DOMAIN>][<ID_TOKEN>]
  PROPOSED_VALUE: schema-valid full record

MUTABLE_STATE_BASELINE_SEEDS:
- Use SET to canonical STATE_ path with COMMON_SEED_FIELDS.

IMMUTABLE_SCHEME_BASELINE_SEEDS:
- Use SET to canonical path inside one immutable baseline-bearing SCHEME module.
- Lawful target modules:
  - SCHEME_HEXACO
  - SCHEME_DARK_TRIAD
  - SCHEME_ASQ
  - SCHEME_MMPI
  - SCHEME_BACKGROUND
- Requires INSTANTIATION_MODE = TRUE.
- Outside instantiation, attempted immutable baseline mutation is SCHEME_IMMUTABLE_BASELINE_WRITE.

COMMON_SEED_FIELDS:
- SOURCE_COT: COT_CHARACTER_INSTANTIATION_PROCESS
- STRENGTH: HIGH
- MECHANISM_TAG: INSTANTIATION_SEEDING
- EPISTEMIC_TAG: COMMITTED_FACT
- EVIDENCE_REF: USER_CONFIRMATION:<instantiation confirmation id>
- JUSTIFICATION_CATEGORY: DIRECT_APPLICATION
- JUSTIFICATION: instantiation seeding

PACKET_COMPLETENESS:
- Every proposal must satisfy UPDATE_CASCADE_REGISTRY.PROPOSAL_ENTRY_SCHEMA before scratchpad entry.
- Pipe alternatives, placeholders, or unresolved candidate values must be resolved before scratchpad entry.

=== SECTION_BREAK ===

=== SECTION: INSTANTIATION_BOUNDARY_RULE ===

- This COT is the lawful first-time seeding exception path.
- Immutable baseline SCHEME values may be prepared only during instantiation.
- Ordinary runtime COTs do not mutate immutable baseline domains.
- INSTANTIATION_MODE distinguishes seeding from runtime mutation.
- Governance remains the sole persistent writer; this COT only proposes seed packets.

=== SECTION_BREAK ===

=== SECTION: FINAL_SEEDING ===

AFTER_EXPLICIT_USER_CONFIRMATION:
- Emit complete seed proposal set into PROPOSED_UPDATES_REGISTRY.
- Do not commit directly.
- Governance validates and commits.
- INSTANTIATION_MODE remains TRUE through final commit cycle.
