=== SECTION: VERIFICATION_CHECKLIST ===

[[LLM_INSTRUCTION]]: Run in order. Each check yields PASS, WARN, or FAIL and a reason code from CHECKLIST_REASON_CODE_MAP.

01) AUDIT_CLOSURE
- Verify every primary-pass proposal has exactly one FINAL_ACTION_LOG closure: COMMITTED, SUPPRESSED, DOWNGRADED, or VETOED.

02) OPERATION_VALIDITY
- Verify strict OPERATION_TYPE vocabulary, forbidden-alias absence, and operation behavior per CANONICAL_TOKEN_DICTIONARY and STATE_GOVERNANCE_AND_COMMIT.

03) CANONICAL_PATH_INTEGRITY
- Verify canonical roots, TARGET_MODULE/TARGET_FIELD agreement, no legacy roots, no [NONE] as ID, no record stubs as concrete records.

04) ORDINAL_AND_BAND_LIMITS
- Verify enum legality, one-step ordinal limits, one-band qualitative limits, SET endpoint limits, lawful TRANSITION targets, and categorical lifecycle SET usage.

05) EMPTY_VALUE_SEMANTICS
- Verify blank, NONE, [NONE], record stubs, and registry-record pairs follow CANONICAL_TOKEN_DICTIONARY.EMPTY_VALUE_FORMS.

06) INVARIANTS_AND_CAPS
- Verify SCHEME invariants, immutable-baseline write prohibition, BODY terminal-state/immune rule, skill invariants, memory linkage/caps, modifier schema/lifecycle, registry-record coherence, DPF cap, prediction gate, goal gate, and permanent skill mutation support.

07) COMMIT_PROVENANCE
- Verify every persistent change traces to committed proposal lineage; no orphaned commits; DYNAMICS directives were not direct writers; schematic directives were expanded before scratchpad entry.

08) EPISTEMIC_AND_JUSTIFICATION
- Verify EPISTEMIC_TAG, JUSTIFICATION_CATEGORY, mapping consistency, COMMITTED_FACT EVIDENCE_REF, disclosure boundary, and PERCEIVED_OTHER_VALENCE inference default.

09) OVERRIDE_PROOF
- Verify override-gate proposals carry lawful INVOKED_RULE_NAME, NARRATIVE_CUE_REFERENCE, SCHEME_INVARIANT_NOTE, and MECHANISM_TAG.

10) CANONICAL_FORM
- Verify commit-bound artifacts normalized, write-surface tokens preserved, no non-canonical residue, and persistent modules declare READ_VISIBILITY_CLASS.

11) READ_BOUNDARY
- Verify character-cognition COTs did not read GOVERNANCE_INTERNAL modules; governance runtime was read only by governance band authorities.

12) TRACE_COMPLETENESS
- Verify exactly one trace per priority slot through PRIORITY_17; empty cycles use EMPTY_CYCLE_FORM; always-run COTs use low-activity trace. Do not verify PRIORITY_18 here.

13) SELECTED_ACTION
- Verify SELECTED_ACTION strict schema, empty-impulse PASSIVE_OBSERVATION fallback, ACTION_SOURCE_IMPULSE validity, and no presumed external success/world resolution/internal-state certainty.

14) OUTPUT_CONGRUENCE
- Verify communication output matches SELECTED_ACTION action/target, remains subjective, marks inference, avoids unselected actions, and does not assert other entities' internal states as fact.

15) MODIFIER_LIFECYCLE
- Verify active-overlay model, in-place refresh/replacement, lawful coexistence, expiry/removal clearance, registry coherence, and no covert baseline rewrite.

16) INSTANTIATION_COMPLETENESS
- On first non-instantiation cycle after instantiation, verify required SCHEME baselines and STATE seeds are populated; skip otherwise unless re-instantiation invoked.

17) FIRES_WHEN_DISCIPLINE
- For non-exempt priority 01–15 COTs, any impulse or non-trace proposal requires at least one satisfied FIRES_WHEN anchor cue.

CHECKLIST_REASON_CODE_MAP:
- 01: AUDIT_CLOSURE_INCOMPLETE (FAIL)
- 02: OPERATION_TYPE_INVALID or INVALID_ORDINAL_TRANSITION (FAIL)
- 03: INVALID_PATH_ROOT or INVALID_TARGET_FIELD or REGISTRY_RECORD_PAIR_VIOLATION (FAIL)
- 04: INVALID_ENUM_VALUE or INVALID_ORDINAL_TRANSITION or STEP_LIMIT_EXCEEDED (FAIL)
- 05: MALFORMED_PROPOSAL_SCHEMA or INVALID_ENUM_VALUE or LINKAGE_REFERENCE_VIOLATION or REGISTRY_RECORD_PAIR_VIOLATION or INSTANTIATION_INCOMPLETE (FAIL)
- 06: SCHEME_INVARIANT_VIOLATION or SCHEME_IMMUTABLE_BASELINE_WRITE or REGISTRY_RECORD_PAIR_VIOLATION or MODIFIER_SCHEMA_VIOLATION or DPF_PREDICTION_CAP_EXCEEDED or IMMUNE_TERMINAL_STATE_CONFLICT (FAIL)
- 07: COMMIT_ORPHANED (FAIL)
- 08: EPISTEMIC_TAG_VIOLATION or JUSTIFICATION_CATEGORY_TAG_MISMATCH or COMMITTED_FACT_WITHOUT_EVIDENCE or EVIDENCE_REF_UNRESOLVED (FAIL)
- 09: OVERRIDE_PROOF_INCOMPLETE (FAIL)
- 10: TRANSLATION_VIOLATION (FAIL)
- 11: READ_BOUNDARY_VIOLATION (FAIL)
- 12: COT_TRACE_MISSING (WARN)
- 13: SELECTED_ACTION_FALLBACK_VIOLATION (FAIL)
- 14: OUTPUT_INCONGRUENCE (WARN)
- 15: MODIFIER_LIFECYCLE_VIOLATION or specific DYNAMICS_TEMPORARY_MODIFIERS sub-code (FAIL)
- 16: INSTANTIATION_INCOMPLETE (FAIL)
- 17: COT_FIRED_WITHOUT_ANCHOR_CUE (WARN)

=== SECTION: REMEDIATION_PROPOSAL_GENERATION ===

[[LLM_INSTRUCTION]]: Classify outcome and append governance-runtime SET proposals. Post-verification commit resolves them same-cycle.

CYCLE_OUTCOME_CLASSIFICATION:
- PASS: zero violations and zero warnings
- WARN: zero violations and one or more warnings
- FAIL: one or more violations

SHARED_PROPOSAL_FIELDS:
- SOURCE_COT: COT_UPDATE_VERIFICATION
- TARGET_MODULE: STATE_GOVERNANCE_RUNTIME
- OPERATION_TYPE: SET
- STRENGTH: MODERATE
- MECHANISM_TAG: VERIFICATION_RESULT_RECORDING
- EPISTEMIC_TAG: INFERENCE
- JUSTIFICATION_CATEGORY: DIRECT_APPLICATION
- INVOKED_RULE_NAME: GOVERNANCE_CORRECTIVE

ON_PASS:
- SET [STATE_GOVERNANCE_RUNTIME][LAST_VERIFICATION_RESULT] = PASS
- SET [STATE_GOVERNANCE_RUNTIME][LAST_COMMIT_CYCLE_ID] = current commit cycle id
- NARRATIVE_CUE_REFERENCE: VERIFICATION_PASS_CLEAN
- SCHEME_INVARIANT_NOTE: SCHEME_GOVERNANCE_RUNTIME overwrite-on-verification

ON_PASS_WHILE_QUARANTINE_ACTIVE:
- Emit ON_PASS proposals plus DYNAMICS_GOVERNANCE_RUNTIME.QUARANTINE_CLEAR proposals.
- NARRATIVE_CUE_REFERENCE: VERIFICATION_PASS_CLEAN
- SCHEME_INVARIANT_NOTE: quarantine clear conditions satisfied

ON_WARN:
- SET [STATE_GOVERNANCE_RUNTIME][LAST_VERIFICATION_RESULT] = WARN
- Do not engage quarantine.
- NARRATIVE_CUE_REFERENCE: VERIFICATION_WARNINGS_PRESENT
- SCHEME_INVARIANT_NOTE: warning recorded without quarantine

ON_FAIL:
- SET [STATE_GOVERNANCE_RUNTIME][LAST_VERIFICATION_RESULT] = FAIL
- If dominant violation maps to QUARANTINE_NEXT_CYCLE, emit DYNAMICS_GOVERNANCE_RUNTIME.QUARANTINE_ENGAGEMENT proposals.
- If remediation is WARN_AND_PROCEED, emit only LAST_VERIFICATION_RESULT.
- If remediation is ROLLBACK, suppress rollback with ROLLBACK_NOT_ACTIVE and use WARN_AND_PROCEED behavior.
- NARRATIVE_CUE_REFERENCE: dominant violation reason code
- SCHEME_INVARIANT_NOTE: violation remediation policy applied
