=== SECTION: SCHEME_SCRATCHPAD ===

[KEEP: Purpose & Role]
Immutable structural definition of the volatile COGNITIVE_SCRATCHPAD workspace. Instantiated per cycle for intermediate calculations, impulse registry, proposal collection, DPF snapshot, selected action output, temporary coordination flags, governance audit logging, normalization audit tracking, domain runtime summaries, and cascade trace accumulation.
READ_VISIBILITY_CLASS: CHARACTER_VISIBLE

Lifecycle invariants:
- INSTANTIATE at cycle start
- POPULATE by COTs
- READ by synthesis and governance
- COMMIT via STATE_GOVERNANCE_AND_COMMIT
- VERIFY via COT_UPDATE_VERIFICATION
- WIPE completely after verification

[KEEP: Relationship to Other Modules]
Informs: All COTs, COT_DECISION_SYNTHESIS, STATE_GOVERNANCE_AND_COMMIT, COT_UPDATE_VERIFICATION.
Is Informed By: Narrative input and SCHEME_ constraints.

=== SECTION: INVARIANTS ===

- All writes occur through COT or system actors only.
- Proposal schema fields are complete per UPDATE_CASCADE_REGISTRY.PROPOSAL_ENTRY_SCHEMA.
- Impulse schema fields are complete per UPDATE_CASCADE_REGISTRY.IMPULSE_ENTRY_SCHEMA.
- Impulses use canonical field casing.
- Scratchpad is fully wiped post-verification (no carryover; cross-cycle governance signal lives in STATE_GOVERNANCE_RUNTIME).
- Governance audit must provide final-action closure for every received proposal.
- Normalization audit must be populated whenever commit-bound or display-bound normalization is relevant; uninitialized fields default to PENDING.
- Reasonable per-cycle bounds enforced for proposals and impulses.
- INSTANTIATION_MODE is set TRUE only by COT_CHARACTER_INSTANTIATION_PROCESS workflow.
