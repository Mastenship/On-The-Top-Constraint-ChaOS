=== SECTION: QUARANTINE_ENGAGEMENT ===

ON_VERIFIED_UNISOLATABLE_FAILURE:
- Only when STATE_GOVERNANCE_OVERLAY.REMEDIATION_POLICY.SYSTEMIC_QUALIFICATION_GATE confirms a new residual, non-isolatable QUARANTINE_NEXT_CYCLE_VIOLATIONS fault, and no active or pending unresolved recovery case exists:
  - PROPOSE SET:
    TARGET_FIELD: [STATE_GOVERNANCE_RUNTIME][QUARANTINE_MODE]
    PROPOSED_VALUE: TRUE
    JUSTIFICATION: exceptional bounded containment
  - PROPOSE SET:
    TARGET_FIELD: [STATE_GOVERNANCE_RUNTIME][QUARANTINE_ENGAGED_CYCLE_ID]
    PROPOSED_VALUE: current commit cycle id
    JUSTIFICATION: beginning of bounded recovery episode
  - PROPOSE SET:
    TARGET_FIELD: [STATE_GOVERNANCE_RUNTIME][QUARANTINE_REASON_CODES]
    PROPOSED_VALUE: append verified systemic reason code; FIFO-evict oldest if cap 5
    JUSTIFICATION: bounded recovery diagnostic
  - PROPOSE SET:
    TARGET_FIELD: [STATE_GOVERNANCE_RUNTIME][RECOVERY_DIRECTIVE]
    PROPOSED_VALUE: concrete governance-only instruction (max 240 characters) identifying reason code, affected target or UNKNOWN, lawful correction, and release evidence
    JUSTIFICATION: capped reformation reminder tied to pending reason codes

NON_REENGAGEMENT_RULE:
- If QUARANTINE_MODE is TRUE, do not re-engage or overwrite QUARANTINE_ENGAGED_CYCLE_ID.
- If QUARANTINE_MODE is FALSE with outstanding QUARANTINE_REASON_CODES, do not automatically re-engage while the existing recovery case awaits resolution or operator review.
- An ordinary FAIL, isolated proposal fault, modifier-lifecycle sub-code without actual persistent corruption, or WARN does not engage quarantine.
- Canonical reason codes and their inherited FAIL classifications do not alone prove systemic impact.

=== SECTION: QUARANTINE_CLEAR ===

[[LLM_INSTRUCTION]]: Same-cycle engagement/clear remains forbidden. Bounded recovery release is independent of PASS/WARN/FAIL outcome; no unchanged full-cycle quarantine may recur indefinitely.

ON_BOUNDED_RECOVERY_CYCLE_COMPLETE:
- If QUARANTINE_MODE is TRUE and QUARANTINE_ENGAGED_CYCLE_ID is a prior cycle:
  - PROPOSE SET [STATE_GOVERNANCE_RUNTIME][QUARANTINE_MODE] = FALSE
  - PROPOSE SET [STATE_GOVERNANCE_RUNTIME][QUARANTINE_ENGAGED_CYCLE_ID] = NONE
  - When and only when the original systemic cause is verified resolved: PROPOSE SET [STATE_GOVERNANCE_RUNTIME][QUARANTINE_REASON_CODES] = [NONE] and PROPOSE SET [STATE_GOVERNANCE_RUNTIME][RECOVERY_DIRECTIVE] = NONE
  - Otherwise leave QUARANTINE_REASON_CODES unchanged and produce an operator-review diagnostic in governance trace.
  - JUSTIFICATION: bounded recovery cycle completed; independent lawful narrative development must resume.

ON_PENDING_RECOVERY_RESOLVED:
- If QUARANTINE_MODE is FALSE with nonempty reason codes, only verified structural resolution or explicit governance-authorized operator review may PROPOSE SET [STATE_GOVERNANCE_RUNTIME][QUARANTINE_REASON_CODES] = [NONE] paired with PROPOSE SET [STATE_GOVERNANCE_RUNTIME][RECOVERY_DIRECTIVE] = NONE.
- A generic PASS, unrelated warning, or lack of further proposals does not prove root-cause repair.

SAME_CYCLE_GUARD:
- If QUARANTINE_ENGAGED_CYCLE_ID equals current commit cycle id, no clear path may clear quarantine.
- Release applies after one full following recovery cycle, never in the engagement cycle itself.
- Retained reason codes while QUARANTINE_MODE is FALSE are a pending-review signal, not authority for another blanket hold.

NARRATIVE_CONTINUITY_BOUND:
- Quarantine affects commit eligibility, not the character's subjective realization or Dungeon Master control of the world.
- Independently safe proposals must remain eligible through STATE_GOVERNANCE_OVERLAY.QUARANTINE_POLICY.PRIMARY_RECOVERY_ADMISSION.
- Do not construct new persistent repairs outside the standard lawful proposal pipeline.
