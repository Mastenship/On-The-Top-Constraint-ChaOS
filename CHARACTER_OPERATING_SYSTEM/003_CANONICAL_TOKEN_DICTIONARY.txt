=== SECTION: STRICT_OPERATION_VOCABULARY ===

ALLOWED_OPERATION_TYPE:
- SET
- TRANSITION
- ADD_MODIFIER
- REMOVE_MODIFIER
- CAP
- VETO

FORBIDDEN_OPERATION_ALIASES:
- CREATE_NEW_RECORD
- UPDATE
- INCREMENT
- DECREMENT

OPERATION_SEMANTICS_MINIMUM:
- SET names explicit lawful endpoint or schema-valid payload; it does not bypass movement, enum, invariant, cap, or override-proof limits.
- TRANSITION applies canonical relative directive to lawful ordinal ladder.
- Categorical fields use SET unless SCHEME declares transition ladder.
- ADD_MODIFIER and REMOVE_MODIFIER operate on STATE_TEMPORARY_MODIFIERS.
- CAP applies bounded ceiling only where permitted.
- VETO suppresses lower-precedence or disallowed mutation.

GOVERNANCE_RECONCILIATION_ACTIONS:
- INVARIANT_FORCED_CORRECTION is a bounded governance reconciliation action, not a proposal OPERATION_TYPE.
- It is generated by STATE_GOVERNANCE_AND_COMMIT only during cross-field invariant reconciliation, only on enumerated invariants, and only as a one-band correction of a single existing committed field.
- It preserves single-writer discipline because STATE_GOVERNANCE_AND_COMMIT remains the sole writer; it is enumerated and bounded, so it is not unconstrained proposal generation.
- It is always audit-logged in the commit pass that emits it.

CANONICAL_RELATIVE_TRANSITION_DIRECTIVES:
- ONE_STEP_UP
- ONE_STEP_DOWN
- ONE_STEP_TOWARD_BASELINE
- ONE_STEP_TOWARD_NEUTRAL

TRANSITION_DIRECTIVE_BINDING_RULE:
- A relative transition directive is lawful only as the PROPOSED_VALUE of an OPERATION_TYPE TRANSITION proposal.
- A relative transition directive appearing as a SET payload is a malformed proposal payload.

=== SECTION: ORDINAL_LADDER_AUTHORITY ===

[[LLM_INSTRUCTION]]: Ordinal step legality and one-step movement are evaluable only against a declared ladder. An ordinal field declares its ladder inline in its owning SCHEME as ORDINAL with members in ascending order.

ORDINAL_DECLARATION_RULE:
- An ordinal field is declared ORDINAL with members in ascending ladder order.
- Bracket position is the canonical ladder; step counting uses bracket position.
- BASELINE_ANCHOR defaults to the first bracket member; a field whose baseline differs declares BASELINE_ANCHOR <member> inline after the bracket.
- ONE_STEP_TOWARD_BASELINE and ONE_STEP_TOWARD_NEUTRAL resolve toward BASELINE_ANCHOR.
- A field may declare OFF_LADDER <member>; an off-ladder member is reached only by SET, never by relative transition.
- A field treated as ordinal by any DYNAMICS module without an ORDINAL declaration in its owning SCHEME surfaces as SCHEME_INVARIANT_VIOLATION.

CATEGORICAL_DECLARATION_RULE:
- A field declared ENUM without ORDINAL is categorical.
- Categorical movement uses SET to explicit endpoint or a SCHEME-declared transition map.
- Relative transition directives are unlawful on categorical fields.

PERCEPTUAL_SNAPSHOT_DECLARATION_RULE:
- A categorical field may declare PERCEPTUAL_SNAPSHOT inline when it represents a whole-cycle perceptual or clinical reading rather than a laddered quantity.
- A PERCEPTUAL_SNAPSHOT field is exempt from one-step movement limits by design and may SET to any lawful endpoint in one cycle.
- The exemption is intentional and must be declared inline; an undeclared intensity-looking ENUM remains an ordinary categorical field.

=== SECTION: EVIDENCE_REF_POLICY ===

EVIDENCE_REF_FIELD:
- Required when EPISTEMIC_TAG = COMMITTED_FACT.
- Optional otherwise.

EVIDENCE_REF_VALUE_FORMS:
- MEM_XX
- PRD_XX only when RESOLVED or RESOLVED_NEGATIVE
- PRIOR_COMMIT:<COMMIT_CYCLE_ID>:<PROPOSAL_ID>
- USER_CONFIRMATION:<CONFIRMATION_ID>
- CYCLE_CUE:<CYCLE_ID>:<CUE_TOKEN>
- [MEM_XX, MEM_XX, MEM_XX] for persistence clusters of three or more memories

EVIDENCE_REF_PREDICTION_RULE:
- A PRD_XX is evidence-eligible only in a settled outcome state: RESOLVED or RESOLVED_NEGATIVE.
- Both forms establish a settled prediction outcome as fact.
- FALSIFIED is not a clean resolution event and is not evidence-eligible.
- ACTIVE predictions are never evidence-eligible.

DISCLOSURE_BOUNDARY:
- Direct disclosure may establish that a statement occurred.
- Another entity's internal state remains INFERENCE or SPECULATION unless substrate grants direct access.

ENFORCEMENT:
- Missing COMMITTED_FACT evidence: COMMITTED_FACT_WITHOUT_EVIDENCE
- Unresolvable evidence: EVIDENCE_REF_UNRESOLVED
- CYCLE_CUE is lawful only when cue alone reaches COMMITTED_FACT threshold.

=== SECTION: READ_VISIBILITY_CLASS_ENUM ===

READ_VISIBILITY_CLASS: ENUM [CHARACTER_VISIBLE, GOVERNANCE_INTERNAL]

GLOSS:
- CHARACTER_VISIBLE: readable by character-cognition COTs and governance.
- GOVERNANCE_INTERNAL: readable only by governance band authorities.

SUBFIELD_VISIBILITY_RULE:
- A module may declare a default READ_VISIBILITY_CLASS and override visibility on named subfields.
- A subfield declared GOVERNANCE_INTERNAL inside a CHARACTER_VISIBLE module is readable only by governance band authorities.

WRITE_VERSUS_READ_NOTE:
- Read-visibility governs read access only.
- Write/append eligibility to a GOVERNANCE_INTERNAL subfield is separately enumerated by the owning module's ACCESS_RULES.
- A lawful character-cognition append to a GOVERNANCE_INTERNAL append-only subfield (for example CASCADE_TRACE) is not a read and is not a READ_BOUNDARY_VIOLATION; only a read-back is.

ENFORCEMENT:
- Character-cognition read of GOVERNANCE_INTERNAL module or subfield: READ_BOUNDARY_VIOLATION

=== SECTION: READ_DERIVATION_RULE ===

[[LLM_INSTRUCTION]]: An Informs relationship from a GOVERNANCE_INTERNAL module to a character-cognition template denotes design-time derivation, not runtime read.

RULES:
- Canonical token, path, operation, epistemic, and ID conformance is compiled into character-cognition COT templates at authoring time.
- Character-cognition COTs satisfy canonical contracts without runtime read of any GOVERNANCE_INTERNAL module.
- Conformance compiled into a template is not a READ_BOUNDARY_VIOLATION; only a runtime read of a GOVERNANCE_INTERNAL surface by a character-cognition COT is.

=== SECTION: SCHEME_MODULE_CONVENTION ===

SCHEME_SUBTYPES:
- STRUCTURAL_SCHEMA: field shapes, enums, invariants, creation requirements; no character-specific values.
- IMMUTABLE_BASELINE_BEARING: schema plus instantiation-time baseline values fixed after seeding.

IMMUTABLE_BASELINE_BEARING_MODULES:
- SCHEME_HEXACO
- SCHEME_DARK_TRIAD
- SCHEME_ASQ
- SCHEME_MMPI
- SCHEME_BACKGROUND

RUNTIME_RULES:
- STATE_ modules store mutable runtime values.
- SCHEME_ modules are read-only during runtime.
- Immutable baseline-bearing SCHEME values may be set during instantiation only, or by explicit architecture-level watershed-equivalent override.
- Runtime write to immutable baseline-bearing SCHEME outside instantiation: SCHEME_IMMUTABLE_BASELINE_WRITE.
